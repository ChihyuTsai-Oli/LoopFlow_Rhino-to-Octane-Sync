# LoopFlow R2O 2.0 — 開發任務與路徑

契約以 `資料契約.md` 為準；即時狀態只記 `重構進度.md`。

## 執行規則

- **能做就做、需確認再停**（R2B／R2O 共用開發原則）：AI 在已決契約與本檔範圍內直接推進文件、空殼、可自動驗證的實作並提交推送短期分支；僅在下列情況停下來問使用者——改已決 ED／ECO、凍結使用者可見名稱／檔名／package 顯示名、破壞性操作、本機安裝正式 runtime、或與決策明顯衝突無法用「2.0 修正」帶過。
- 一次一個 repo／一台電腦／一個 AI。
- 從 `v2-development` 建 `codex/v2-<scope>`。
- **可測＝兩端同批**：Rhino＋Octane Lua 同一功能同批；Models 的「消費」＝手動置換驗收（無 LiveLink）。
- **跨產品**：R2B 主鏈已穩；本產品可進 A01 與功能碼。
- **Octane 空殼入口**：B 骨架可先交付可跑的 stub Lua／shortcut（無業務邏輯），再於 C／D 垂直任務接功能；對外仍是單支腳本＋快捷鍵，對內可模組化。
- 前期規劃當原則；衝突先改決策表。
- 不把 authoring 混進 LiveLink 主鏈任務。

## 階段與任務（摘要）

| ID | 任務 | 產出重點 |
|---|---|---|
| R2O-A01～A06 | 盤點／命名／schema／Point ID／shortcut 邊界／fixtures | 只改文件；加厚契約 |
| R2O-B01～B04 | source 骨架、foundation、Rhino adapter、Octane loading | 可載入、隔離；**可含 Octane stub Lua 入口** |
| R2O-C01 | **Models 兩端** | Rhino USDZ 安全鏈＋Octane **手動置換**驗收 |
| R2O-C02 | **Scatter 兩端** | producer＋consumer 同批 |
| R2O-D01 | **Point 兩端** | `type_id`、刪受管節點 |
| R2O-D02 | **Camera 兩端** | JSON；可開關 real-time |
| R2O-E* | Open／shortcut／lifecycle | 診斷與安裝 |
| R2O-F* | Authoring baseline | 不擴充、不阻塞 |
| R2O-G01 | migration | 掃描／備份／一次轉／回滾；只測副本 |
| R2O-G02 | build／`build-release` | **Rhino `.yak`**（畫面名 `loopflow Rhino to OctaneRender Sync`）；Octane Lua 不進包、PM 說明放 GitHub。與 LoopFlow 2.0 相同：同一份 yak 上 PM＋Release；tag 不覆寫；文件資料夾戳記＝套件版號 |
| R2O-G03 | RC／`rc-validation` | 隔離端到端；成敗中斷 last-good |

任務表以本檔為準。

## 建議波次

1. 文件骨架＋發布契約（本批）→ R2B 主鏈已穩，可進 A01。
2. A01–A06 → B 骨架。
3. C01（Models 手動置換）→ D02 Camera → D01 Point → C02 Scatter（與已決操作序一致，實作可按可測性微調，明顯衝突再改表）。
4. E–G：shortcut、authoring、**Rhino yak**、migration、RC。公開使用說明等本產品程式完成後與 R2B 一起寫。
