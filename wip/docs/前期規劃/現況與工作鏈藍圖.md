# R2O 2.0 — 現況與工作鏈藍圖

本文件整理穩定 1.x 與現行重構 SSOT 的現況與意圖，供決策表對照。**不在此填寫裁決**；待確認事項只寫在 `資料生態決策表_三家建議.md`。

## 產品一句話

Rhino → 安全發布檔案 → Octane（Lua LiveLink）消費：Models（USDZ）、Scatter、Point（燈光／家具代理對齊）、Camera。

## 已定案邊界（細節見決策表 E 區）

- 目標 `v2.0.0`；`main` 凍 1.x；整合 `v2-development`
- 乾淨重建、發布時一次切換；核心不留 v1 雙寫
- 三邊界：Rhino Producer｜Octane LiveLink｜Authoring Tools（本輪不擴充 authoring）
- 執行時設定／即時檔：工作檔旁 `_LoopFlow_Config/loopflow_R2O/`
- 來源 `.3dm` 零變更；pending → validate → atomic last-good
- 與 R2B 只共用文件層安全語彙，不共用 runtime package
- Rhino Python-first；Octane 維持 Lua

## 現行 1.x 觀察（待盤點成 2.0 契約）

- 安裝在 `%APPDATA%\...\scripts\LoopFlow_R2O\`；`R2O_Path.txt`、Shortcuts、Camera／Point Lua、USDZ
- 指令習慣名：Models、Scatter、Point、Camera、Open（開發暫定見 `../rhino指令.md`）
- Octane：LiveLink Lua、節點前綴、shortcut；Authoring 另組 Lua
- Scatter＝家具／Block 實例發布；Point＝對齊代理／燈
- **Camera 兩端分工（1.x）**：Rhino `R2O_Camera` 以 event＋約 0.2s 節流**持續寫**同步檔；Octane `LiveLink_R2O_Camera.lua`（快捷鍵 Ctrl+Q）為**執行一次**才套用最新值（非背景輪詢）。早期若持續讀檔曾有 lag，故採此模式。
- **Camera 2.0 意向（已決）**：Rhino 維持持續發布並補 trailing write（ED-13＝A）；Octane **再試可開關的 real-time 輪詢**，可關回手動一次（ED-19＝B）；資料改 JSON（ED-18＝B）

## 建議工作鏈（草案，非正式流程契約）

```text
開案（.3dm 已存檔）
→ Open／Health
→ Models 發布 USDZ（含材質後處理；失敗＝整體失敗）
→ Camera 發布 JSON
→ Point 發布 JSON（燈光／代理對齊）
→ Scatter 發布 Block USD（接在 Point 之後；可與 Models 獨立）
→ Octane：手動置換 USDZ；Camera 可開 real-time 輪詢或手動一次套用；Point LiveLink parse＋apply
→ 失敗保留 last-good；來源檔不變
```

Camera 兩端說明見決策表 `R2O-ED-13`／`R2O-ED-19` 與 `操作流程模擬.md`。強制與否、Proxy 身分、節點碰撞等 → 見決策表。
