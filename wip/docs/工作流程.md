# LoopFlow R2O 2.0 — 工作流程

權威操作順序。細節模擬見 `前期規劃/操作流程模擬_合併.md`；衝突以本檔與 `資料契約.md` 為準。

## 操作主線

**Models → Camera → Point → Scatter**。

開發時：**Rhino 與 Octane（Lua）同一通道同批實作**。R2B 主鏈已穩，本產品可進功能碼。安裝：Rhino 走 Package Manager `.yak`；Octane Lua 由 GitHub 說明安裝（不進 yak）。

## 開案

1. 隔離 1.x／2.0 LiveLink、shortcut、輸出。
2. 已存檔 `.3dm`；`R2O_Open`＋Health。
3. Octane：指標或手動路徑（XF-ED-04＝C）。

## Models

1. `R2O_Models` → 後處理驗證 → atomic USDZ。
2. Octane：**手動置換** last-good（無 Models LiveLink）。

## Camera

1. Rhino 持續寫 JSON（trailing write）。
2. Octane：**可開 real-time 輪詢**；關＝Ctrl+Q／跑一次腳本。
3. Thin Lens Camera 須從 Render Target **Expand out** 成獨立節點，腳本才能找到；收折在 Target 內則無法套用。

## Point

1. `type_id` 路徑映射；不寫回 Rhino。
2. JSON 發布；缺 Proxy／未知 type 略過並報告。
3. 刪 type：權威 snapshot 成功後刪受管節點（ED-10＝A）。
4. 僅作 Scatter **資產定義**用的 Block，建議放在 `USD::<名稱>` 等**非** Point 根前綴圖層，避免被 `R2O_Point` 掃成同步點位。

## Scatter

接在 Point 後；單項失敗可繼續。

### 建 Block 慣例（作者／資產）

1. **建立 Block 之前**：先把物件在世界裡擺「正」（建議正面朝 ±X 或 ±Y，與專案其他 USD 軸向約定一致）。
2. **再建立 Block**：定義的插入點／局部原點對齊世界 `(0,0,0)`，幾何相對該原點擺好。
3. 若與 Blender／場景 USD 模型坐向差 90／180／270：在 **Block 定義內**旋轉物件對齊即可，不必靠 Octane 端硬掰。
4. 如此 Point 送來的 instance 旋轉套在 Scatter Proxy 上時，Octane 方向才一致。

（1.x 說明只寫「原點對齊 (0,0,0)」不夠；精確意思是上列「先擺正再建 Block」。）

### 匯出執行安全（與上列不同）

`R2O_Scatter` 匯出過程可暫移 instance；**結束後**來源 `.3dm` 內的 Block **不得**永久留在世界原點（成功／失敗／中斷皆還原）。

## 失敗停點（摘要）

未存檔停；後處理失敗 last-good 不動；半寫 JSON 不 apply；real-time lag → 關輪詢改手動。
