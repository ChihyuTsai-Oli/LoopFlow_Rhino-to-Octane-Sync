# LoopFlow R2O 2.0 — 工作流程

權威操作順序。細節模擬見 `前期規劃/操作流程模擬_合併.md`；衝突以本檔與 `資料契約.md` 為準。

## 操作主線

**Models → Camera → Point → Scatter**。

開發時：**Rhino 與 Octane（Lua）同一通道同批實作**。安裝：Rhino 走 Package Manager `.yak`；Octane Lua 由 GitHub 說明安裝（不進 yak）。

使用操作序仍是 Models → Camera → Point → Scatter。**開發波次**：相機、點位、Models 已合入 `v2-development`。**Scatter 本批**。

## 開案

1. 隔離 1.x／2.0 LiveLink、shortcut、輸出。
2. 已存檔 `.3dm`；`R2O_Open`＋Health。
3. Octane：指標或手動路徑（XF-ED-04＝C）。

## Models

1. 已存檔後，Rhino `R2O_Models` 三個英文視窗（對齊 R2B）：排除記號（預設 `//`，圖層路徑含此文字就不匯出；空白＝不排除）→ 階層圖層樹（可捲動；含子圖層）→ 勾選幾何類別（Point／Curve 預設不勾）。記住上次成功的圖層／記號／類別。
2. 寫入 `_LoopFlow_Config/loopflow_R2O/models/models.usdz`（pending → 材質提升到圖層 Xform → 驗證 → atomic）。`_-Export` 不把中文／括號路徑丟進指令列：優先父目錄 8.3＋ASCII 檔名，否則先寫 `%TEMP%\r2o_models_pending.usdz` 再拷回 pending。失敗不碰舊檔；不自動存 `.3dm`；結束後來源狀態還原。
3. Octane：**無** Models Lua。第一次把場景載入這份 `models.usdz` 並接材質。接口跟 **Rhino 材質名稱** 走（不同圖層／物件同名＝同一接口；R2O 不改材質名）。之後 Rhino 覆寫同一檔時，**不要**按 Reload mesh／Load new mesh；**關掉 Octane 再開**，已連結的 USDZ 會在啟動時跟上。這是 Studio+ 2026.4 限制（開著時不會可靠重讀連結檔）。改 Rhino 材質名＝新接口。
4. 空圖層／取消任一步／沒勾類別：停止，不發布。Camera／Point／Scatter 檔不被 Models 刪掉。

## Camera

1. 已存檔後，Rhino `R2O_Camera` 開持續發布（作用中**透視**視埠；非透視停止）。`R2O_Camera_Push` 手動推一次。
2. 寫入 `_LoopFlow_Config/loopflow_R2O/live/camera.json`；成功時更新 `%APPDATA%\LoopFlow\R2O\current_project.json`。
3. Octane 跑 `R2O_Camera.lua`（Ctrl+Q）：**套用目前 `camera.json` 一次即結束**。Studio+ 2026.4 無法在不鎖 UI 下做 realtime（已試視窗／輪詢）。之後每要對齊再跑一次。
4. Thin Lens Camera 須從 Render Target **Expand out** 成獨立節點；場景必須**恰好一台**。零台或多台英文說明、不改節點。
5. 熱鍵：編輯 `lua/R2O_Shortcuts.txt`（`__Open_Shortcuts.lua`）→ 跑 `__Setup_Shortcuts.lua` → 重掃 Octane 腳本資料夾。家中中文路徑已通過相機實機。

## Point

1. 已存檔後，Rhino `R2O_Point` 掃 **`R2O::` 子圖層**的 Point 與 Block（含隱藏／鎖定；根層 `R2O` 本身不掃）。`USD::` 下的資產 Block 不會被掃到。
2. 寫入 `_LoopFlow_Config/loopflow_R2O/live/point.json`；成功時更新本機指標。
3. Octane 跑 `R2O_Point.lua`：**套用一次即結束**（無預設熱鍵）。Scatter 出現在**場景根**（可直接接 Geometry 輸入／輸出，不必炸開）。前綴 `R2O_Point_`。已有同名節點只改變換、不搬位置。刪除清掉此前綴且已不在 JSON 裡的受管節點。若場景裡還有舊的空 `R2O_Point` 群組，可手動刪。
4. `type_id`＝完整圖層路徑。同末層不同父＝兩個節點。改名＝新類型。Rhino 已刪的類型：下次成功套用後刪受管 Scatter。
5. 空清單仍發布／套用（用來清掉已刪類型）。缺 Proxy 不擋點位（幾何之後用 Scatter 接）。

## Scatter

接在 Point 後；可獨立跑。單項失敗可繼續，但來源 Block **不得**留在原點。

1. 已存檔後，Rhino 選一個或多個 Block（支援預選），跑 `R2O_Scatter`。非 Block 會停。相同定義只匯一次。
2. 寫入 `_LoopFlow_Config/loopflow_R2O/scatter/<Block定義名>.usd`（pending → 驗證非空 → atomic）。檔名保留中文，不洗成 `unnamed_block`。兩個定義洗成同一檔名則整批停止、不寫檔。`_-Export` 仍走 8.3 或 TEMP。
3. 匯出時可暫移該 instance 到原點；**結束後**（成功／失敗／中斷）還原位置、選取、`doc.Modified`。不自動存 `.3dm`。
4. Octane：**沒有** Scatter Lua（與 1.x 相同）。把各 USD 接到對應 Point Scatter 的 Geometry。第一次載入該檔；之後覆寫同一檔則 **關再開** Octane。不要 Reload mesh／Load new mesh。
5. 建議資產 Block 放在 `USD::`（不在 `R2O::`），才不會被 Point 掃成點位。建 Block 慣例見下。

### 建 Block 慣例（作者／資產）

1. **建立 Block 之前**：先把物件在世界裡擺「正」（建議正面朝 ±X 或 ±Y，與專案其他 USD 軸向約定一致）。
2. **再建立 Block**：定義的插入點／局部原點對齊世界 `(0,0,0)`，幾何相對該原點擺好。
3. 若與 Blender／場景 USD 模型坐向差 90／180／270：在 **Block 定義內**旋轉物件對齊即可，不必靠 Octane 端硬掰。
4. 如此 Point 送來的 instance 旋轉套在 Scatter Proxy 上時，Octane 方向才一致。

（1.x 說明只寫「原點對齊 (0,0,0)」不夠；精確意思是上列「先擺正再建 Block」。）

### 匯出執行安全（與上列不同）

`R2O_Scatter` 匯出過程可暫移 instance；**結束後**來源 `.3dm` 內的 Block **不得**永久留在世界原點（成功／失敗／中斷皆還原）。

## 失敗停點（摘要）

未存檔停；後處理失敗 last-good 不動；半寫 JSON／USDZ 不 apply。Camera：Octane 僅手動套用一次。Models／Scatter：Octane 關再開才重讀已連結檔（不要 Reload／Load new mesh）。Scatter：非 Block 停；檔名碰撞整批停、不寫檔；單項失敗可繼續；還原失敗＝整次失敗。

## 磁碟示意（相機檔名已凍結；根與 R2B 對齊）

```text
<已存檔 .3dm 同層>/
  _LoopFlow_Config/loopflow_R2O/
    config.json / r2o.log
    live/camera.json（含 camera_pending.json）
    live/point.json（含 point_pending.json）
    models/models.usdz
    scatter/<Block定義名>.usd
    lua/                 # 僅測檔根：開發期 Octane 入口拷貝，不是每案必有
```

本機指標（不是交換檔）：`%APPDATA%\LoopFlow\R2O\current_project.json`

## 不涵蓋

Authoring 功能擴充；Models LiveLink；自動升級混用。Octane Lua 不進 Rhino yak。
